## Where things stand
Level 14 is complete across all parts (14a, 14b, 14c) on branch `feature/level-14c-bank-feed-and-connectors`.
- Part 14a: Commercial bank schema migration 0006, non-superuser role `ashfall_bank_api`, RLS tenant isolation, pooled connection safety, outbox schema 2 with UUIDv5 routing to `upi.payments`.
- Part 14b: Authenticated, signed, and idempotent bank REST APIs, raw percent-encoded path signing, replay protection with transport clock isolation, and comprehensive schemathesis fuzzing.
- Part 14c: Bank-feed projection from world records, mock bank connectors with shadow and live modes, in-process and signed HTTP parity, R7 visibility rules preserving failed payment boundaries, outbox relay to Kafka with schema version 2, and strict refusal of boundary leaks such as transaction purpose.

Register counts: built 58, partial 12, planned 22, deferred 1 (total 93). Current amendment: A-033.

## Decisions and why
- Bank-feed projection and allow-lists: `world/bank_feed.py` projects simulation output into bank-visible payment sides, account lifecycle and device events, and fraud complaints, strictly validating every record against field allow-lists (`BANK_VISIBLE_PAYMENT_FIELDS`, `BANK_VISIBLE_ACCOUNT_EVENT_FIELDS`, `BANK_VISIBLE_COMPLAINT_FIELDS`, `GENUINE_DEVICE_DETAIL_FIELDS`, `GANG_DEVICE_DETAIL_FIELDS`) and raising `ProjectionLeakError` on unexpected fields (such as `purpose`).
- R7 failure domain visibility: Failed payments are partitioned strictly by failure domain. Sending banks record all failed attempts (`side='debit'`), whereas receiving banks record failed payments (`side='credit'`) only when the failure domain is `receiver_bank`, ensuring receiver visibility preserves real-world banking boundaries.
- Assumptions on missing simulator channels and VPAs: Simulator world records lack channel and VPA fields; `channel_value` defaults to `"upi_app"` as an explicit config assumption in `config/bank_feed.yaml`, and `counterparty_vpa` is left empty `""`.
- Migration 0008 for debit-only sender device columns: Adds optional `sender_device_fingerprint` and `sender_os_generation` columns to `transactions` in `migrations/0008_add_sender_device_columns.sql`. These fields are populated exclusively on debit sides.
- Per-bank operating modes: Replaces scalar `default_bank_mode` in `config/bank_api.yaml` with a per-bank `bank_modes` mapping (`bank_0`, `bank_1`, `bank_2` configured individually as `"shadow"` or `"live"`).
- Live mode allow-only behavior until Level 19 (14-6): Because scoring models are not trained or enabled until Level 19 and decision endpoints return `"unscored"`, live mode evaluates incoming responses and falls back to `"allow"`, recording fallback counts (`live_fallbacks`) rather than blocking legitimate simulation flow.
- Deterministic idempotency keys: Hook decision requests are idempotently keyed by the planned payment ID (`make_decision_idempotency_key`) because the synchronous simulator hook only observes the planned payment ID.
- Hybrid dispatch architecture: Hook decision requests are dispatched per planned payment during simulation via `asyncio.run_coroutine_threadsafe`, while transaction sides, account events, and complaints are projected and dispatched after simulation completes (`send_feed`), respecting the plan's fallback while guaranteeing causality via global multi-key sorting `(event_time, bank_id, record_kind, original_index)`.
- Gang device event filtering: Gang planner device event kinds that lack an equivalent commercial bank API lifecycle kind are dropped and counted in `dropped_device_events_by_kind`.
- In-process and HTTP transport parity: `InProcessBankClient` (direct database pool) and `SignedHttpBankClient` (over `httpx.ASGITransport` using HMAC-SHA256 request signing) implement the `BankTransport` protocol and produce identical stored rows.
- Webhook delivery deferred to Level 19: Background webhook delivery is deferred to Level 19 because decisions remain unscored throughout Level 14.

## Known gaps and future work
- Real per-payment channel: The world simulation lacks explicit payment channel tracking; all payments assume `channel="upi_app"`.
- Virtual Payment Addresses (VPA): Simulator payments lack virtual payment addresses; `counterparty_vpa` is left empty.
- Unmapped gang device events: Gang planner device event kinds that have no commercial bank API lifecycle mapping are dropped and counted rather than emitted.
- Webhook delivery: Background webhook delivery loop to commercial bank endpoints is deferred to Level 19 when fraud scoring is active.
- Accounts opened mid-run: Accounts opened mid-run cannot receive real-time hook decisions because `account_bank_map` is established before simulation via `prepare_world`.
