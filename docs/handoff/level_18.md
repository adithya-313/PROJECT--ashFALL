# Level 18 handoff: the mule account and payment models

Generated by `scripts/level18_handoff.py`. Every number is SIMULATED.

## What was built

Key amendments in `docs/research/amendments.md`, each with its own 'What changed' text:

- **A-043:** Escalation now has a repeats policy, set in `config/evaluation.yaml` under `escalation_repeats`. `daily_escalations` takes `repeat_policy`, either `every_day` (the Level 17 behaviour, re-ranking every bank-day from scratch) or `once_per_world`: an account escalated on one day is under review for the rest of its world, is not a candidate on a later day, and the slot goes to the next account in rank order. Per-bank-day capacity is computed exactly as before, and same-day behaviour is unchanged. `evaluate_world` forwards the policy, and the Level 18 pilot and the Level 18 sanity oracle read the configured value; Level 17 callers keep the `every_day` default and are unchanged.
- **A-063:** Pre-registers the Level 18 task 3 console generator: the frozen input files, the output envelope, the nine console files and the exact fields each copies, the definition of the seven leakage checks, the yield/E1 mapping and its one computed number, the no-scoring rule, and the `18a` handoff note.
- **A-064:** Pre-registers Level 18 task 10: two generated model cards (markdown and JSON) for `mule_account_xgb` and `mule_payment_xgb`, built only from the nine committed console files of A-063, and a new "mule model quality gate" CI job that checks the committed cards against a new threshold config, every threshold carrying `derived_from`. No model is fitted, loaded, scored or changed and model v1's gate is untouched.
- **A-070:** Pre-registers Run B, the behaviour-only account model, before any Run B row is read by the driver or any Run B result exists: the exact config file and its sha256, the cpu device, the eight dataset folders, the four world counts, the out-root, the worktree commit, issue #154's serving rule verbatim, and the once-only test scoring.
- **A-070a:** Amends A-070 rulings 7 and 8 before launch: stage 5 may score test in the same run, with the test outputs sealed until the serving decision is committed and pushed; and the validation recall at capacity of both models is computed after the run by one new read-only script.
- **A-071:** Records the serving decision of issue #154: Run A's account model (behaviour and label-network features) is served; Run B's behaviour-only model stays the documented fallback for a bank with no complaint history.
- **A-072:** Records that Run B's leakage check 6b failure is the known A-051 simulator finding. Run B's card shows it as "FINDING — documented limitation (A-051)" with its numbers, never as a pass. Run B is then added to the console files and the account model card as the fallback model for banks with no complaint history.

## Known limitations

- **Leakage check 6b (A-051):** account identifiers alone reach average precision 10.415 times the base rate, limit 2.0. Recorded as `fail` for Run A and Run B.
- **Payment stress ranking:** stress truth AP 0.1220 (0.0233 to 0.3831).
- **Account models under stress:** not run: no stress worlds supplied.
- **Payees at another bank:** no payee score; 1115957 test payments have a NaN payee risk for that reason.
- **Learning curve still rising** (Run A, training worlds: validation truth AP): 40: 0.2414, 80: 0.3763, 160: 0.4506, 320: 0.5647. more_training_worlds_needed is true.
- **Capacity:** In these worlds both 0.25% and 0.5% capacity mean exactly 1 review per bank-day (max 172 active accounts per bank-day on test, 168 on validation); a real capacity curve needs larger worlds.
- **Flaky test:** `test_time_estimate_within_margin` on CI runners, GitHub issue #187.
- **Open register items:** 17-1 (rule_5 recall) and 17-5 (tuned rule thresholds not committed) move to Level 19+.
- **17-3:** closed in the register, covered by the multi-world rules baseline above. A-043 is about repeat-escalation counting, not coverage.
